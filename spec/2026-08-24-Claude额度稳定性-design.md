# Claude 额度稳定性设计

## 问题

Claude Desktop 已经写入官方 `/usage` 缓存，但应用把缓存有效期设为 5 分钟，界面过期阈值却是
150 秒。缓存超过 150 秒后，界面会显示“正在重新连接”；同时自动刷新因检测到缓存存在而直接返回，
无法恢复到正确状态。

## 方案

- Claude Desktop 的官方本地缓存仍是第一数据源，不增加网络请求频率。
- 展开刘海时立即读取一次缓存，保证查看每个任务消耗时尽快拿到 Claude Desktop 最新结果。
- 缓存和界面统一使用 150 秒的新鲜度阈值。
- 缓存过期时明确显示“等待 Claude 客户端更新…”，不把旧值当作实时值，也不误报网络重连。
- 缓存过期且已开启凭据兜底时，自动刷新进入现有受节流和失败退避保护的网络数据源；成功后清除等待状态。
- 不修改 Claude 设置、token、Cookie 或 Keychain 内容。

## 验证方式

1. 单元测试覆盖新鲜缓存、过期缓存与等待状态。
2. 集成测试读取本机 Claude Desktop 官方缓存，确认能获得额度且缓存时间可用。
3. 完整测试、Release 构建与测试版应用打包通过。
